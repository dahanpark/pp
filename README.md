# 프라이어팰리스 리노베이션 공감 리포트

최신본은 **2026년 11월호 Rev12, A4 가로 HTML 22쪽**입니다. 4쪽의 대수선 우선 검토 이유를 다섯 개 키워드로 간결하게 정리하고, 6쪽 행정 검토 아젠다에 준비위원회 발족 및 추진위원회 확대를 별도 항목으로 담았습니다.

## 현재 관리 파일

- `src/report.html`: 최신 웹 원본
- `src/report-a4.css`: 데스크톱 A4 화면과 인쇄에 공통으로 쓰는 배치·글씨 규칙
- `releases/2026-11/261103_프라이어팰리스 리노베이션 공감리포트_26년 11월_Rev12.html`: 글꼴·사진·스타일을 포함한 독립 HTML 보관본
- `data/renovation-progress.json`: 날짜·상태·의결 예정·가결 조건을 구분한 누적 경과 원장
- `data/report-build.json`: 현재 발행 규격·페이지 수·법규 문구 협의 상태
- 프로젝트 폴더의 `output/최신_공감리포트.html`: 항상 갱신하는 최신 사본
- 프로젝트 폴더의 `output/2026-11/`: 날짜와 개정번호별 HTML 보관본

`output`은 이 Git 저장소의 상위 프로젝트 폴더에 있습니다. 새 결과물은 HTML만 발행합니다. 기존 PDF와 이전 개정본은 보관 이력입니다. 개별 설문 응답·인증 자료·대화 원문은 올리지 않습니다.

이번 변경은 추정 실행금액 300억원, 10월 28일 입대의 토의 경과, 준비위원회에 앞선 협의체 사전 검토를 반영합니다. 로드맵은 10단계이며 협의체 구성안은 **11월 표결 예정**입니다. 공식 발족으로 표시하지 않습니다. 설문 246건의 수치·내용은 유지했으며 현재 10~13쪽에 있습니다.

## A4 화면과 인쇄 확인

데스크톱의 각 페이지는 297×210mm입니다. 화면 폭이 좁으면 A4 미리보기 전체를 같은 배율로 줄이고, 인쇄에서는 배율을 원복합니다. 모바일은 읽기 편하게 세로로 재배치합니다. 인쇄 전용 글씨 축소나 페이지별 가변 용지는 사용하지 않습니다.

상단 **A4 가로 인쇄**를 누르면 글꼴과 사진을 모두 불러온 뒤 브라우저 인쇄창을 엽니다. Chrome에서 A4·가로·배율 100%·여백 없음·배경 그래픽 사용을 기준으로 확인합니다. 브라우저 머리글·바닥글은 끕니다. 물리 프린터의 용지·인쇄 가능 영역은 장치 설정을 확인합니다.

매번 변경 후 `scripts/check_a4_report.cjs`로 페이지별 텍스트 잘림, 화면·인쇄의 위치와 글씨 차이, 사진·글꼴 로딩, 모바일 넘침·비교표 방식명 표시를 확인합니다. 검사에서 문제가 있으면 실패 코드로 종료합니다. 임시 인쇄 PDF와 PNG는 `tmp/`에만 만들고, 실제 인쇄 화면까지 검수한 뒤 HTML을 발행합니다.

`scripts/build_a4_report.cjs --approved`로 사용자와 협의한 법규 페이지를 포함해 최신 HTML과 `output` 사본을 갱신합니다. 새 법규 문구는 먼저 사용자와 협의하고 원출처를 확인합니다. 확인 대기 중에는 `--publish --omit-rationale`로 해당 페이지를 제외할 수 있습니다. 날짜와 상태는 먼저 누적 원장에서 갱신합니다. 새 내용 반영 후 화면·인쇄·모바일 검사를 다시 통과해야 합니다.

## 운영 원칙

1. 리포트 내용과 디자인은 모바일 HTML 원본인 `src/report.html`에서 먼저 수정합니다.
2. HTML 확정본을 `releases/YYYY-MM/`에 보관합니다. PDF는 화면 동일본을 먼저 만들고 A4 인쇄 사본을 따로 만듭니다.
3. HTML과 PDF를 각각 화면·인쇄 매체에서 확인합니다.
4. 인증 제출 자료, 참가자 명단, 녹화 영상 등 민감한 첨부물은 사용자가 직접 관리하며 Git 저장소에 넣지 않습니다.
5. 변경 단위마다 Git 커밋을 남겨 발행 이력을 관리합니다.

대수선 주민 의견조사 결과는 `src/survey-results.html`과 11월호 8~11쪽에 동일한 집계 데이터로 표시합니다. 조사 기간은 2026.10.7~10.25(19일간), 수록 응답은 10.25 23:11까지 접수된 246건입니다. 제공된 원본의 10.26 응답 1건은 마감 기준에서 제외했습니다. 문항별 유효 응답 수는 미응답에 따라 다릅니다. 공지방 인원 138명·354명은 응답자 수와 다릅니다.

## PDF 생성·확인

HTML 상단의 **HTML 동일 PDF** 버튼을 사용합니다. 화면 동일본은 브라우저의 인쇄용 CSS를 사용하지 않고 `screen` 미디어의 288dpi 무손실 이미지를 원래 화면 크기로 PDF에 넣습니다. PDF 엔진의 폰트·그림자 재해석도 생기지 않으며, 원본의 글씨 크기와 요소 위치를 바꾸지 않습니다. 화면 보존을 위해 이미지 방식으로 만들었으므로 PDF 텍스트 선택·검색은 지원하지 않습니다. 각 페이지 높이가 달라 모두 A4 가로 크기는 아닙니다. 모바일 화면은 읽기 편하게 세로로 재배치됩니다.

종이 인쇄에는 **A4 가로 PDF** 버튼을 사용합니다. 원본 페이지를 A4 한 장에 맞추는 균등 배율만 적용하며 줄바꿈이나 내부 배치를 바꾸지 않습니다. 긴 원본 페이지는 A4에 맞추며 축소됩니다. 원본 글씨 크기 유지와 모든 페이지의 A4 가로 규격 고정은 별개의 출력 조건입니다.

생성 순서: `node scripts/export_screen_pdf.cjs` → `node scripts/capture_screen_pages.cjs` → `python scripts/merge_screen_pdf.py` → `python scripts/verify_screen_pdf.py` → `node scripts/build_html_release.cjs`. 실행 환경에는 Playwright·Chrome, pypdf·ReportLab·Pillow·NumPy·pypdfium2가 필요합니다. `scripts/build_pdf.cjs`는 이전 호의 출력 코드이며 현재 화면 동일본 생성에는 사용하지 않습니다.

검증 근거는 보관본과 같은 이름의 `-layout-check.json`에 저장합니다. Rev08 대비 페이지 내 텍스트·글씨 크기·줄간격·색상·좌표 비교, 캡처 직전의 글씨·좌표 변화 여부, PDF에 들어간 이미지와 화면 원본의 픽셀 일치 여부 및 실제 PDF 렌더링을 확인합니다. 주민 대화 원문·설문 개별 응답·인증 자료는 Git 저장소에 올리지 않습니다.
